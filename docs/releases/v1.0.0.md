# v1.0.0 — 2026-11-24

**The first stable release of the Auth API.**

A self-hosted authentication and authorization service for multi-tenant applications:
password and social login, two-factor and passkeys, RBAC, an OIDC provider, an admin GUI
and a public documentation site — behind one Go service and one PostgreSQL database.

## Highlights

### Authentication and sessions

- Email/password registration, login, JWT access tokens and rotating refresh tokens with
  Redis-backed blacklisting; per-application password policies (length, complexity,
  history, maximum age) and per-application token TTLs.
- Email verification, password reset, magic-link login and passkeys (WebAuthn), including
  passwordless discoverable credentials.
- Google, Facebook and GitHub OAuth2 with account linking, an explicit merge confirmation
  and HMAC-signed, single-use, browser-bound `state` tokens.
- Server-side session registry with list/revoke endpoints.

### Two-factor and recovery

- TOTP, email codes, SMS codes, backup email and passkey as a second factor.
- Recovery codes and trusted devices.
- **SMS recovery**: a one-time code by SMS when the primary factor is unavailable —
  including users whose primary method is TOTP.

### Multi-tenancy and authorization

- Tenants own applications; applications own users, roles, permissions, branding, email
  templates and policies. The same email in two applications is two isolated users.
- RBAC with per-application roles (`admin`, `member`, `viewer`) and granular permissions.
- Admin API key and per-application API keys with scopes and usage analytics.

### OIDC and SSO

- Each application can act as an OpenID Connect provider: discovery, JWKS, authorization
  code + PKCE, token, userinfo, introspection and revocation.
- Session groups link applications for cross-app SSO with configurable global logout.

### Operations

- Admin GUI for tenants, applications, users, roles, email templates, webhooks, OIDC
  clients, session groups, IP rules, API keys, logs and monitoring.
- HMAC-signed webhooks with delivery history and retries.
- Activity logs with anomaly detection, CSV export and retention cleanup.
- `GET /health` and authenticated Prometheus `GET /metrics`.

### Documentation

- Public documentation site: <https://gjovanovicst.github.io/golang-auth-api/>
  — task-oriented user guide (start / integrate / deploy) and a generated API reference.

## Install

Multi-arch container image (`linux/amd64`, `linux/arm64`), signed and attested:

```bash
docker pull ghcr.io/gjovanovicst/golang-auth-api:1.0.0

docker run -p 8080:8080 --env-file .env ghcr.io/gjovanovicst/golang-auth-api:1.0.0
```

Or with the Compose file from the repository, or the archives attached to this release
(`auth-api_1.0.0_{linux,darwin}_{amd64,arm64}.tar.gz`, `auth-api_1.0.0_windows_amd64.zip`).

Create the first admin account with the host binary (the image contains only the API):

```bash
go run ./cmd/setup -username admin -password 'a-strong-password' -email admin@example.com
```

Then open `/gui/login` and the Swagger UI at `/swagger/index.html`.

## Verify what you run

```bash
cosign verify \
  --certificate-identity-regexp "^https://github.com/gjovanovicst/golang-auth-api/" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  ghcr.io/gjovanovicst/golang-auth-api@<digest>

sha256sum -c checksums.txt
```

The image is published with `provenance` and `sbom` attestations.

## Breaking changes

None — this is the first stable version. The `1.0.0-alpha.N` tags were development
milestones and were never supported for production.

## Upgrade from 1.0.0-alpha.7

1. Back up the database (`make migrate-backup` or `pg_dump`).
2. Apply migrations shipped with the release: `make migrate-up`.
3. Pull `ghcr.io/gjovanovicst/golang-auth-api:1.0.0` and restart the service.
4. Check `GET /health`, log in with password + 2FA, open the admin GUI.
5. Rotate `ADMIN_API_KEY` and `JWT_SECRET` if they were ever shared.

## Security

- bcrypt cost 12 for admin passwords and OIDC client secrets.
- OAuth `state` tokens are signed, single-use and bound to the initiating browser.
- Email template preview iframes no longer allow same-origin access.
- The container runs as an unprivileged user (`app`) with `GIN_MODE=release`.
